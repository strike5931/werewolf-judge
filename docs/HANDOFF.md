# 接手說明

給下一個要改這個專案的人（或下一個 AI 工作階段）。目的是讓你不用重新摸索，就知道程式怎麼組成、怎麼改、怎麼驗證、哪裡踩過坑。

- 這套工具怎麼用、三種玩法、我們這桌的規則：看 [README](../README.md)。
- 牌面和介面圖的畫法、提示詞：看 [ART.md](ART.md)。
- 這份只講開發。

## 一分鐘版

- 整個工具是**一個 HTML 檔**：`werewolf-judge.html`。沒有框架、沒有打包、沒有後端。
- `index.html` 是建置產物，**不要手改**。改完原始檔後跑 `python3 tools/build.py`。
- 改完一定要跑無頭測試：`cd tools/e2e && node run.mjs`（約 6 分鐘，需要網路）。
- 推到 `main` 就會自動部署到 GitHub Pages。**使用者說「推上去」才推。**

## 原始檔怎麼編輯

`werewolf-judge.html` 裡有一行 `const ART={...};/*ART*/`，是 1.9 MB 的圖檔資料。這造成幾個限制：

- **不要整個檔讀進來看**，會塞爆。用 `grep -n` 找位置，用 `sed -n '起,迄p' | cut -c1-400` 看片段。
- **不要用會重寫整行的工具去碰那一行。**
- 實際的做法是寫一段 Python，用「完全相符的字串取代」加上次數檢查：

```python
f='werewolf-judge.html'; s=open(f,encoding='utf-8').read()
def rep(a,b,c=1):
    global s; assert s.count(a)==c,(a[:60],s.count(a)); s=s.replace(a,b)
rep("舊字串","新字串")
open(f,'w',encoding='utf-8').write(s)
```

- 取代「從 A 到 B 之間」的區塊時，**B 要選緊鄰的下一個標記**。曾經因為結尾標記選太遠，把 `ART` 那一行也一起刪掉，只能 `git checkout` 還原。
- 改完檢查語法：把 `<script>` 抽出來跑 `node --check`。

程式裡每一大段都有 `/* ---------- 標題 ---------- */` 的分隔註解，用它找位置最快：
狀態、規則引擎、快速測試、畫面（共用／設定／發牌／夜晚／白天）、底部面板、卡牌 3D、動作、計時器、連線房間、線上模式、螢幕恆亮。

## 程式怎麼運作

### 一個狀態、一個重繪

- 全域變數 `S` 是整局的狀態。`render()` 每次都把 `#app` 整個重畫。
- 畫面由 `S.phase` 決定：`setup`（設定）→ `assign`（發牌）→ `night` ⇄ `day` → `over`。對應 `vSetup`、`vAssign`、`vNight`、`vDay`、`vOver`。
- 按鈕不綁事件。所有可點的東西帶 `data-a="動作"` 和 `data-p="參數"`，由一個全域點擊監聽交給 `act(a,p)` 處理。`act` 結尾固定做 `save(); render()`。
- 下拉選單和輸入框用 `data-c`，走另一個 `change` 監聽。
- 連線相關的按鈕用 `data-n`，卡牌晃動用 `data-m`，各有自己的監聽。**這幾種不會進復原紀錄。**

### 復原

`snap()` 在會改狀態的動作前把 `S` 複製一份進 `H`（上限 60 份）。`UI` 這個陣列列出「純介面、不用存」的動作。新增動作時要判斷它屬於哪一種。

### 存檔

存在瀏覽器的 `localStorage`，三把鑰匙：

| 鑰匙 | 內容 |
|---|---|
| `wwj-state-v1` | `{S, H}`，對局狀態和復原紀錄 |
| `wwj-net-v1` | `NET`，連線房間的狀態（裁判端：房號、誰坐哪；玩家端：房號、自己的憑證和名字） |
| `wwj-theme` | 外觀設定 |

`S` 的結構看 `fresh()`，夜晚當下的選擇在 `S.nt`，結構看 `newNt()`。

### 規則引擎

- `nightSteps()` 回傳這一夜有哪些步驟、順序為何。**所有夜晚順序的規則都在這個函式。**
- `vNight()` 依目前步驟畫出台詞和選項。變數 `lock` 設成 `true` 就會鎖住「下一步」（例如身份還沒記、商人只選了一半）。
- `resolveNight()` 在按「天亮，結算」時算出誰死。
- `kill(id, 原因)` 處理出局和連帶效果（開槍、殉情、警徽、狼弟覺醒），會把待處理事項放進 `S.todo`。
- `winner()` 判斷勝負。

改規則時，先看 README「我們這桌的規則」。那一段是使用者那一桌實際確認過的，和網路上的通用規則不完全相同。

### 圖

- `ART` 物件：角色代號 → 牌面圖；`_night`、`_day`、`_good`、`_evil`、`_back` 是介面圖；`i_角色代號` 是座位徽章。
- `BAN` 物件：每張牌底部橫幅的中心高度，`build.py` 從圖上量出來，用來疊角色名字。
- 兩者都由 `build.py` 寫入，不要手改。

### 連線（裁判手機當主機）

用 PeerJS（WebRTC）。函式庫只在需要時才從 CDN 載入，有完整性雜湊。

- 裁判端的 Peer ID 是 `wwj-room-房號`。玩家連上後送 `hello`（帶自己的隨機憑證），之後座位綁在憑證上，所以重新整理能接回。
- **裁判端是唯一的真相來源。** 玩家端不存對局狀態，只顯示裁判送來的 `state` 訊息。
- `stateFor(憑證)` 為每個玩家各算一份狀態，**只放他該看到的東西**。新增任何要給玩家的資訊，都要從這裡加，並想清楚會不會洩漏別人的身份。
- 玩家端收到後先過 `pvClean()`：只留已知欄位、檢查型別和範圍。**新增欄位時兩邊都要加**，否則會被濾掉。
- `save()` 會順便呼叫 `netPush()`，所以狀態一變就自動廣播。

三種玩法（`NET.play`）：`cards` 現場有牌、`phone` 現場沒牌、`online` 線上玩。

### 線上玩怎麼把選擇送到玩家手機

沒有另外寫一套規則，而是**重用裁判畫面**：

1. `nightOpts()` 把 `vNight()` 產出的畫面解析一次，找出目前步驟所有可按的選項。
2. `seatActs(步驟, 玩家)` 決定這個座位在這一步能做哪些動作。
3. `actFor(玩家)` 把兩者合起來，放進送給那位玩家的狀態裡。
4. 玩家點了之後送回 `{t:'act', a, p}`，裁判端的 `hostAct()` **再驗一次**這個選項此刻確實存在且沒被停用，然後呼叫和裁判自己點擊完全相同的 `act(a,p)`。

好處是規則只有一份。代價是：**改 `vNight()` 裡選項的 `data-a` 名稱時，要同步改 `GT` 和 `STEPACT` 這兩張表。**

### 斷線與暫停

玩家每 4 秒送心跳，12 秒沒消息算離線。只有線上玩會暫停（`pausedSeats()`），因為現場玩時大家晚上本來就會把手機蓋著。

## 改完怎麼驗證

```bash
python3 tools/build.py
```

```bash
cd tools/e2e && node run.mjs
```

第一次要先在 `tools/e2e` 跑 `npm install`。它用的是這台電腦上已安裝的 Chrome，不會另外下載瀏覽器。

測試會開一個裁判加最多八個玩家的無頭瀏覽器，真的透過 PeerJS 連線。可以只跑一組：`node run.mjs cards`、`names`、`phone`、`online`、`pause`。加 `HEADED=1` 可以看畫面。

目前 103 項。新增功能時請一起加斷言，尤其是「誰看得到什麼」這類資訊隔離。

測試涵蓋不到的：

- 真手機、行動網路、鎖屏。
- 守衛、狼美人、狼王、白狼王、白痴、騎士的流程（測試用的板子沒有這些角色）。
- 手機晃動連動用的是模擬的感應器數值。
- 畫面長相。要看畫面的話，用 Playwright 截圖（`reducedMotion:'reduce'`，手機尺寸 390×844）。

工具裡另外有「選單 → 快速測試」，是給裁判手動驗證規則情境用的，定義在 `TESTS`。

## 踩過的坑

**環境**

- macOS 會問「要不要允許尋找區域網路上的裝置」。無頭測試的瀏覽器之間要互連，沒允許的話玩家會永遠卡在連線中。這是系統設定，要請使用者自己按。
- GitHub Pages 的部署偶爾會因為 GitHub 自己的映像檔伺服器故障而卡住。不是我們的問題，等一下或推下一版就好。
- 本機預覽不要用 `file://` 開，`localStorage` 會失效。用 `python3 -m http.server`。
- 在使用者的預覽分頁裡測試時，不要清 `localStorage`。曾經因此弄丟使用者正在進行的一局。要測就用另一個網址（`127.0.0.1` 和 `localhost` 的儲存空間是分開的），或用無頭瀏覽器。

**連線**

- 開著 VPN 的手機連不上，會卡在第三階段。已在加入畫面提醒。
- 連線有三個階段，每段有逾時和原因提示。玩家回報連不上時，請他截那一行字。
- 在 Claude 的私人預覽頁裡，連線和動作感應多半用不了。要測這些得用公開網址或本機。

**介面**

- 動畫只動 `transform`，不要用 `opacity` 做進場。曾經因為淡入動畫卡住，整個畫面看起來是空的。
- 底部面板是有高度上限的直向排列，子元素要設 `flex-shrink:0`，否則內容多時按鈕會被壓扁重疊。
- 卡片區域用 `touch-action:pan-y`，只處理左右拖曳。曾經整個攔下來，結果手機上滑不動頁面。
- 啟動順序：`themeLoad()` 比 `load()` 早跑，那時 `S` 還沒有值。任何啟動時就會執行的程式都要防這個。
- 不要用 `confirm()`、`alert()`，在預覽頁裡會被擋。

**產圖**

- 細節都在 [ART.md](ART.md) 的「試產學到的事」。最重要的兩條：要統一風格就附參考圖；不要寫畫家的名字。
- OpenAI 金鑰從 `OPENAI_API_KEY` 環境變數讀。**不要寫進檔案、不要貼在對話裡。**
- 原圖在 `art/`，沒有進版控。換電腦要另外備份。

## 還沒做的

使用者提過或討論過、目前沒有做的：

- 白天投票、警長競選、警徽移交搬到手機上（線上玩目前仍由裁判記錄）。
- 白狼王自爆、騎士決鬥由玩家在手機上發動。
- 沒有專職裁判、流程自動推進。
- 現場用線上玩時，沒輪到的人也有假動作可按，避免被看出誰在操作。
- 只給某一個座位看牌（有人沒手機時用）。目前的「傳手機看牌」是全員輪一遍。
- 開始後對調座位、交給替補玩家。
- 出局的人看上帝視角。
- 裁判手機換機：匯出和匯入整局狀態。
- 打不通的網路環境（VPN、某些行動網路）需要中繼伺服器才能解，目前沒有。

還沒確認過的：

- 淺色配色在真手機上的對比和小字清晰度。
- 真手機鎖屏觸發暫停的時機（12 秒）合不合適。
- 白狼王、狼美人、騎士、白痴、10 人黑商板子的完整流程，沒有人實際跑過。

## 和使用者合作的方式

這個專案是一位裁判為自己那桌做的，他不寫程式。目前為止的節奏：

1. 他描述需求，常常附群組對話的截圖，裡面是那一桌對規則的討論。**截圖裡的結論就是規格。**
2. 改完、測過、發佈到私人預覽，說明改了什麼、驗證了什麼、沒驗證到什麼。
3. 他回「推上去」才推到 GitHub Pages。
4. 回覆用繁體中文。

規則有疑問時先問，不要照網路上的通用規則自己決定。這一桌的規則有好幾處和通用版不同，README 裡記的才算數。
